## 1. 제품 목표·비목표

**목표:** 첨부 화면처럼 차트 중심의 밀도 높은 단일 거래 워크스페이스를 구현한다. 사용자가 시장 현황 → 차트·호가 → 주문 입력·위험 정보 → 포지션/내역의 순서로 맥락 전환 없이 살펴볼 수 있게 한다. 정보 구조와 행동 패턴을 참고하며, PerpDEX 고유 브랜드·디자인 토큰·문구를 사용한다. 현재 공개 사이트는 Simulation Preview다.

**비목표:** 화면 스크린샷의 픽셀·차트·상표를 그대로 복제, TradingView 라이브러리 또는 상용 기능을 무단 사용, 실시간 시세/가짜 체결을 실제처럼 표시, 지갑/운영 API/온체인 거래를 이 작업으로 활성화, Cross·Unified·TWAP·Chase·TP/SL·유료 Pro 기능을 검증 없이 지원하는 것.

## 3. 레이아웃 및 정보 계층

### 3.1 데스크톱 ≥1280 CSS px (권장 기준 1536×960)

```text
┌────────────────────────── PerpDEX 전역 내비게이션 ───────────────────────────┐
│ 시장 선택 / Mark / Index / 24h / 거래량 / OI / Funding (출처/미연결 표시) │
├──────────────────────────────────┬────────────────┬───────────────────┤
│ Chart | Funding(미지원 표시)     │ Order Book     │ Margin / Leverage │
│ interval / tools(지원 범위만)    │  | Trades       │ Market / Limit    │
│                                  │ Ask · Spread   │ Long / Short      │
│ 캔들 또는 정확히 표시된 MOCK 차트 │ Bid · Depth    │ Size / Preview    │
│ + 가능한 경우 거래량              │ 단위·출처       │ Margin / Risk     │
├──────────────────────────────────┴────────────────┤                   │
│ Positions | Orders | History | Funding ...        │                   │
│ 계정 인증/조회 상태와 데이터 테이블                │                   │
└───────────────────────────────────────────────────┴───────────────────┘
```

- 목표 비율은 **차트 60~64% / 오더북 18~21% / 주문 18~22%**이다. 고정 스크린샷 픽셀 복제보다 각 열의 최소 가독 폭·화면 높이 활용을 우선한다. 주문 티켓은 스크롤 가능하되 주요 CTA를 하단으로 밀려 숨기지 않는다.
- 전역 헤더, 지표 바, 차트 도구·가격축, 주문 폼 섹션, 하단 탭을 시각적으로 구분하되 과한 카드 여백을 줄여 밀도 높은 터미널을 만든다. 차트의 빈 영역을 장식 카드로 대체하지 않는다.
- 계정 패널은 차트·호가 아래에 걸쳐 배치하고 주문 패널은 우측 열에 독립 배치한다. 브라우저 높이가 작을 때 차트/호가/폼/계정의 스크롤 책임을 분리하며 겹침·잘림이 없어야 한다.

### 3.2 반응형 규칙

- **769~1279px:** 차트 우선. 주문 패널의 최소 가독 폭을 확보하고 오더북은 탭/접기 또는 차트 아래 배치. 수평 전체 페이지 스크롤 금지.
- **≤768px:** 시장 요약 → 차트 → 주문 → 접이식 오더북/거래 기록 → 계정 패널의 논리적 DOM/읽기 순서를 보존. 각 섹션 내 스크롤은 명시; 입력·연결·미리보기 타깃 최소 44×44px 권장.
- **200% 확대/좁은 높이:** 컨트롤 겹침, 잘린 가격축, 하단 탭 유실, 연결/미연결 오인을 금지. 현재 모바일 계정 탭 가로 스크롤 및 `aria` 키보드 탐색 유지.

## 4. 데이터 의미/상태 계약 (필수)

| 데이터 | `MOCK_SAMPLE` | `UNAVAILABLE` | `VERIFIED_TESTNET` 조건 |
|---|---|---|---|
| 차트 OHLC·거래량 | 결정적 fixture·샘플 인덱스 사용, 실제 시각·거래량이라 주장 금지 | 도표 대신 명시적 빈 상태 | 체인/신뢰 시세 소스·timestamp·단위·시계열 검증 후 |
| Mark/Oracle/24h/OI/Funding | 실제 계산 가능한 합성 지표에만 명확한 MOCK 레이블 | `—`와 미연결 사유, 카운트다운도 숨김 | 지표 정의·기간·출처·신선도·실패 상태 합의 후 |
| 오더북/스프레드 | 기초 샘플에 기반한 누적값과 계산값만, MOCK 표시 | 빈 호가/스프레드 | 인증된 시장 데이터/정렬·규모·stale 검사 후 |
| Available/Position/Margin/PnL | 타 계정 또는 임의 실잔고처럼 보이는 금액 생성 금지 | 계정 미연결 기본값 | 소유권 인증 계정 API·revision·원자 금액·차단 정책 검증 후 |
| 주문·수수료·청산 | DEMO Preview만, 추정이 허용된 참고 값과 전제 명시 | 계산 불가 항목 `—` | M5~M9 정책/원장/서명/테스트넷 검증과 별도 승인 후 |

- 모든 mock/실 데이터는 영역 가시 텍스트와 스크린리더 접근성 이름 모두에서 구분한다. 실제 시장의 Mark/Oracle 값을 스크린샷에서 하드코딩하지 않는다.
- 미연결 값은 **`0`, `0.00`, `Online`, 실시간 시각, 가짜 수익률**로 대체하지 않는다. 특히 잔고 0과 잔고 미조회는 엄격히 분리한다.
- 지원하지 않는 고급 탭/토글을 활성 버튼으로 꾸미지 않는다. UI 토글은 상태 변경이 실제로 작동하거나 명확히 비활성 처리한다.

## 5. 동작 및 접근성 계약

1. **시장을 바꾸면** 심볼/기초자산 단위/차트/호가/주문 입력/비용 출처가 한 시장으로 동기화된다. 이전 시장의 검토 결과를 무효화한다.
2. **호가/체결 탭**은 클릭, Tab, 방향키(탭 패턴일 경우), Enter/Space로 접근하며 패널의 선택·비선택 상태와 숨김 상태가 일치한다. 기존 MOCK 체결 행은 순번과 Side를 유지한다.
3. **주문 유형·방향·수량·가격·레버리지** 변경은 기존 Preview 유효성·재검토 계약을 보존한다. 입력 오류, limit 검증, 포커스, ESC로 닫기, 동일값 재선택 동작은 기존 회귀를 깨지 않는다.
4. **계정 패널**은 현재 5개 탭의 disconnected/loading/ready/empty/error와 소유권 검증 게이트를 유지하며 오래된 ready 기록을 남기지 않는다.
5. **상태/색상**은 색만으로 Long/Short·매수/매도·에러를 구분하지 않는다. 모든 아이콘에 접근 가능한 이름과 키보드 포커스를 제공한다.
6. **공지/툴팁**이 있다면 포지션 테이블과 주문 입력을 가리거나 키보드 포커스를 가두지 않는다.
